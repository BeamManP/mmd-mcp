# 制作経路 v0.3.0

## 責務

`pose_authoring.py` はモデルファイルのハッシュと初期ボーン位置に基づいて意味ベースのポーズをコンパイルする。`pose_fk.py` は腕チェーンの順運動学と `hand_at` / `palm_facing` の目標探索を担う。実機への適用は `bone_batch.py`（`mmd_batch_bone_keys`）がフレーム別にまとめて行い、`authoring_live.py` の `apply_pose` は内部関数として残る（MCPツールとしては廃止）。既存の単一ボーン操作、ファイル読み込み、キー登録、保存の独立性を保つ。

対応はあにまさ式ミク1.3、MEIKO、Tda式初音ミクV4X 1.00の確認済みファイルに限定する。Tdaでは上半身の回転を上半身／上半身2へ分配し、前腕軸のひねりを手捩りへ設定する。PMXのローカル軸・付与・固定軸情報もプロファイルに返すが、任意のリグへの自動リターゲットは行わない。キャリブレーションは見た目を含む検証が必要。

`motion_document.py` はスパースなボーン・表情キーを保持する厳密なPydanticモデル。名前とフレームの組み合わせは一意。移動は削除とupsert、補間修正は完全なボーンキーのupsertで行う。元documentは変更せず、JSONとVMDは新しいファイルへ保存する。

## 読み取り専用のモデル調査

`mmd_get_model_profile(model_path, bone_name=None, bone_index=None)` はPMD 1.0／PMX 2.0・2.1をボーン・IK節まで解析する。既存の `bones`・ハッシュ・意味ポーズ対応情報に `investigation` を追加した。対象を名前か0始まりインデックスで指定すると、対象からルートへの親階層、関連する付与とIKが返る。名前は日本語／PMX英語の完全一致で、重複はインデックス指定が必要。MMDの選択・フレーム・キー・ファイルを変更しない。

PMXは英語ボーン名、変形階層とフラグ、接続先、付与、固定／ローカル軸、外部親キー、IK反復・角度上限・リンク制限を保持する。PMDは種類・接続先／IK生値・IKチェーンを保持し、種類5と9の回転付与を分けて解釈する。PMDにない明示的ローカル軸やリンク角度制限は補完しない。`derived_hand_geometry` は休止位置からの法線候補であり、掌の表裏や実カメラへの向きを証明しない。

PMXの操作軸をVMD回転の基底変換として使わない。宣言の有無、親階層、計算による推定、未確認の実機挙動を分ける。後続のモーフ・物理節は未解析で、全ファイル検証ではない。参考実装の読み取り項目と照合し、PMD種類別の解釈は [MMD ToolsのPMD変換](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/pmd/importer.py) も確認した。実装は転載していない。

## 角度・補間

MMD 9.32のボーン数値欄からVMD Quaternionへの変換は `Ry(-y) Rx(x) Rz(-z)`。あにまさ式ミクで直接入力した `(10,20,30)` と、同じ角度から出力したVMDの読み戻しが `(10,20,30)` となることを確認した。カメラ角へ流用しない。

曲線の制御点は0〜127。時間方向は `x1 <= x2`。`x,y,z,rotation` は各キーに到着する区間を制御する。VMDの64バイト補間領域は4チャンネルそれぞれの16バイトブロックを持ち、先頭ブロックの単純な4回繰り返しでは独立した曲線にならない。

実機テストでは0→30フレームのセンター移動X/Yを0→10とし、Xだけ `(0,0,0,127)`、Yを線形に設定。15フレームでX=8.90、Y=5.00を確認した。回転も同じ曲線で0→−80度の約88.99%へ進むことを確認した。

PMXの節構造とVMDの補間領域は、MMD Toolsの [PMX実装](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/pmx/__init__.py) と [VMD出力実装](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/vmd/exporter.py) を参照して形式を確認した。実装の転載は行っていない。

## 再現用デモ

```powershell
.\.venv\Scripts\python.exe scripts/demo_authoring.py --model "C:/YourModels/model.pmx" --output "C:/MMD-Test/new-demo"
```

省略時はファイル生成のみ。新しい出力ディレクトリを使う。実機での比較には、対象モデルを選択した、既存アニメーションのない検証シーンを用意し、`--hwnd 12345 --apply` を追加する。スクリプトは指定したウィンドウのみ操作し、起動／終了は行わない。既存の制作シーンへ安易に適用しない。

基準版は0／42／150フレームのポーズ。改良版は12フレームの予備動作、28の通過姿勢、42の行き過ぎ、48／60の落ち着き、90／120の小さな上体変化を加える。全フレームをキー化せず、138→414ボーンキーに編集する。表情もキーで保持する。

VMDを重ねると未記載の古いキーが残る。このデモでは基準版の全キーIDを改良版に含める。異なるキーパターンを比較するときは同じ初期PMMから読み直す。

## プレビューと評価

最大180フレームを順に評価し、各PNG、10fps等のサンプルレートに応じたAVI、コマ一覧を保存する。WGCは現在の表示を取得するため、物理演算の再現性や厳密な描画同期を保証しない。成功時のみ元フレームへ戻す。エラー時の自動復元は手動変更を破壊する可能性があるため行わない。

制作上の判断基準は [操作スキル](../skills/mmd-pose-motion/SKILL.md) を参照する。手の読みやすさはモデルと衣装に依存する。長袖で隠れた指だけから曲げ軸を判断せず、手が見える視点で形を確認し、実際に使うモデルで検証する。

## アクセサリ

X読み込み、一覧・選択、数値・表示・影の変更、親モデル／親ボーン、キー登録をネイティブUI経路で扱う。アクセサリのインデックスを明示して誤対象を防ぎ、読み戻しとフレーム往復でキーを確認する。一括削除は `mmd_delete_accessories`。エフェクト用アクセサリの数値も `mmd_batch_accessories` で編集できる。MMEの割当は既存EMMのMain・オフスクリーン各セクションと材質単位の一括編集に対応する。反映はMMEの設定読込、またはPMM再読み込みで行う。[MME割当](effects.md) を参照。描画順、VAC変換、MMEダイアログの直接操作は未対応。

## ネイティブキーの往復

既存キーは `mmd_edit_actions` / `mmd_select_key_range` で選択し、`mmd_export_file(kind="motion")` で書き出す。
`mmd_inspect_vmd` は値と各チャンネルの補間を読み、`mmd_edit_vmd` は新規ファイルへの時刻・削除・補間編集を行う。
ボーンの補間は各16バイトブロックの有効点を読み書きし、未使用に見える場所のネイティブ物理フラグ等を保持する。
カメラの距離・角度とセルフ影の距離は保存形式の値をそのまま返す。
VMD読込はマージなので、時刻移動・削除を反映する場合は元のライブキーを整理してから読込む。
重力・アクセサリ・外部親などVMDだけで再現できない内容はPMMを使う。
詳細なAPI例と制約は [native-editing.md](native-editing.md)。
